🎯 What is FairPay?

Workers submit evidence URLs; AI validators audit quality against an agreed rubric and vote a tier: HIGH 1.25× / MEDIUM 1.0× / LOW 0.75× / UNVERIFIABLE 0×. Payouts execute automatically from the employer's locked GEN budget.

🔒 Reserved-Liability Recovery (v0.4.0):

Employer can only withdraw budget above the reserved liability - a period reserves its maximum reachable payout (hours × rate × 1.25, rounded up) while any higher outcome is still live (submitted / disputed / adjudicated-with-appeal-open), dropping to exact pay only once truly final. The recovery and appeal paths share one window predicate, so finalize() always stays funded.

🔏 Sealed Evidence (v0.3.0, multi-gateway in v0.4.1):

Evidence is sha256-sealed at submission; mutated evidence at audit time -> MISMATCH, pay 0. v0.4.1 accepts the canonical CID URL from a strict allowlist of four HTTPS IPFS gateways (gateway.pinata.cloud, ipfs.io, dweb.link, w3s.link); integrity stays content-derived, so which gateway served the bytes does not matter.

🧠 Exact Canonical Tiers + On-Chain Reasoning (v0.3.0):

AI returns JSON {tier, reasoning}; leader/validator consensus compares only the tier; explanation stored on-chain.

⚠️ Threat Model (summary)

  • Gateway lookalikes (ipfs.io.evil.com, ipfs.io@evil.com, other scheme/port, query, fragment, traversal, subdomain form) are rejected before any state change by an anchored allowlist regex.
  • Same-CID different-bytes across gateways are caught by the sealed-hash re-check at audit time.
  • Reserved liability always covers the maximum still-reachable payout, so recovery can never defund a live appeal.
